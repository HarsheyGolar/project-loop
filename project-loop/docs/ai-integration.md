# Project LOOP — AI Integration

> **Module:** AI / Integration  
> **Status:** Initial AI analysis foundation complete  
> **AI Provider:** Google Gemini  
> **Model:** `gemini-2.5-flash`  
> **API:** `POST /api/ai/analyze`

## 1. Overview

The AI integration module provides server-side customer-feedback analysis for Project LOOP.

The current implementation accepts a feedback string, validates the request, sends the feedback to Gemini, requests a structured JSON response, validates the returned structure with Zod, and returns the validated analysis to the caller.

The current implementation is intentionally independent of the database layer. Real PostgreSQL persistence will be connected after the Feedback schema and backend integration are finalized.

## 3. File Responsibilities

### `app/api/ai/analyze/route.ts`

The API boundary for feedback analysis.

Responsibilities:

- Accept `POST` requests.
- Parse the incoming JSON body.
- Validate the request using Zod.
- Reject invalid input with HTTP `400`.
- Call `analyzeFeedback()` from the AI service.
- Return the validated AI result as JSON.
- Handle unexpected failures with HTTP `500`.

The route intentionally contains request/response handling rather than Gemini-specific implementation details.

### `lib/ai.ts`

The AI service layer.

Responsibilities:

- Initialize the Google GenAI client using `GEMINI_API_KEY`.
- Define the expected structured response shape.
- Build the feedback-analysis prompt.
- Call the Gemini model.
- Request JSON output from Gemini.
- Parse the returned JSON.
- Validate the AI output using Zod.
- Return a typed, validated analysis result.

Keeping the AI logic in a separate service makes the API route smaller and makes it easier to change the AI provider or model later.

### `.env`

Stores the server-side Gemini API key.

```env
GEMINI_API_KEY=your_api_key_here
```

The real value must never be committed to Git or exposed to the browser.

## 4. API Contract

### Endpoint

```http
POST /api/ai/analyze
```

### Request body

```json
{
  "feedback": "The checkout process is very slow and frustrating."
}
```

### Successful response

The service returns a structured analysis containing:

```json
{
  "sentiment": "negative",
  "summary": "The checkout process is slow and frustrating.",
  "theme": "checkout process",
  "category": "performance"
}
```

The exact summary, theme, and category values are generated by Gemini and may vary by input.

## 5. Request Validation

The API validates incoming feedback with Zod before any Gemini request is made.

Current rules:

- `feedback` must be a string.
- Leading/trailing whitespace is trimmed.
- Empty feedback is rejected.
- Feedback longer than 5000 characters is rejected.

Invalid input returns HTTP `400`.

Example invalid request:

```json
{
  "feedback": ""
}
```

Expected result:

```text
400 Bad Request
```

## 6. Gemini Integration

The AI service uses the official Google GenAI SDK.

The current model is:

```text
gemini-2.5-flash
```

The model is instructed to analyze feedback using four fields:

- `sentiment`
- `summary`
- `theme`
- `category`

The request also specifies an application-level response schema so that Gemini is asked to return structured JSON instead of free-form text.

## 7. Structured AI Response

The expected AI response is conceptually:

```ts
type FeedbackAnalysis = {
  sentiment: "positive" | "neutral" | "negative";
  summary: string;
  theme: string;
  category: string;
};
```

The `sentiment` field is restricted to:

```text
positive
neutral
negative
```

## 8. Response Validation with Zod

Gemini output is not trusted blindly.

The response flow is:

```text
Gemini JSON
    |
    v
JSON.parse()
    |
    v
Zod schema validation
    |
    +---- valid ----> return analysis
    |
    +---- invalid --> throw error
```

This ensures that downstream application code receives the expected structure rather than arbitrary model output.

## 9. Error Handling

### Invalid client input

```text
HTTP 400
```

Used when the request payload does not satisfy the input schema.

### Gemini / server failure

```text
HTTP 500
```

Used when an unexpected error occurs while processing the AI request.

Server-side logs retain the detailed error for debugging; sensitive configuration values must not be exposed in API responses.

## 11. Security Notes

- The Gemini API key is server-side only.
- The API key must be stored in `.env` and excluded from Git.
- The frontend should call the application API route rather than Gemini directly.
- Detailed provider errors should remain server-side and should not be returned directly to users.

## 12. Current Scope vs. Future Integration

### Completed in the current AI foundation

- Gemini API integration
- Server-side model call
- Structured JSON response
- Request validation with Zod
- AI response validation with Zod
- Error handling
- Local functional testing

### Pending backend integration

The current AI service is not yet connected to PostgreSQL Feedback records.

The planned production flow is:

```text
Feedback created/imported
        |
        v
Analyze feedback content
        |
        v

        |
        v

        |
        v
```

This database integration will be implemented after the backend Feedback schema and migration are finalized.

## 13. Planned Project LOOP AI Work

The AI analysis foundation is the first part of the broader AI milestone. The remaining product-level AI work includes:

1. Classifying real feedback on ingest.
2. Storing classification results.
3. Grouping feedback into themes.
4. Building theme trends over time.
5. Implementing Ask LOOP using retrieval and grounded answers.

These features will build on the current `analyzeFeedback()` service rather than introducing a separate AI flow.

## 15. Integration Principles

The AI module follows these principles:

- Keep API routes thin.
- Keep AI-specific logic inside the AI service layer.
- Validate external input.
- Validate model output.
- Keep secrets server-side.
- Keep database integration separate from the initial AI service foundation.
- Prefer reusable service functions over embedding model calls in UI components.
